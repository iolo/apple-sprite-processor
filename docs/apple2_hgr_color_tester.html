Why do colors change?

Position creates hue. An isolated illuminated monochrome sample can appear purple or green, depending on its horizontal parity. Setting a byte's high bit changes the artifact-color phase, yielding blue or orange instead.

Neighboring 1s create white. A run such as 0110 contains neighboring lit samples. It cannot be treated as two independent colored dots: the composite signal tends toward white in the adjoining region.

The byte boundary is awkward. Each byte contains seven samples, so the boundary splits a nominal two-sample color cell. The high bit applies to each byte independently; a mixed-phase boundary cannot be decoded reliably as a single ordinary color cell.

Model limitation: The lower strip uses a simple neighbor rule: an illuminated sample adjacent to another illuminated sample is white; isolated illuminated samples are colored; unlit samples are black. This is not an analog NTSC decoder. Actual colors at transitions depend on surrounding samples, phase shifts, and the monitor/decoder. The orange dashed line marks the byte boundary.

Pixel bits are shown in left-to-right screen order (D0 to D6 for each byte), not conventional binary-number printing order.
